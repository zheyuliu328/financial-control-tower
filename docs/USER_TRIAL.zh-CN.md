# 双表比较界面：15 分钟真人试用方案

**当前状态：尚未执行真人试用。** 本文件是可执行的试用计划和空白记录表。浏览器自动化通过、开发者自测或截图检查都不能填入真人完成率，也不能替代陌生参与者的实际观察。

试用目标：观察一位没有参与开发的分析师，能否从两份外部格式的文件出发，完成复合键与多字段比较，解释需要进一步核对的条目，取得报告，并发现修改输入后旧下载已失效。只使用新造样例，不需要也不应提供客户、账户或个人资料。

## 主持人预先准备（不计入 15 分钟）

1. 准备一位未参与本工具开发的参与者。用代号记录，不要求实名；先征得记录操作和原话的同意。没有同意时不录屏，只做必要的匿名笔记。
2. 从仓库根目录创建独立环境并正常安装当前版本；不要使用可编辑安装。以下命令由主持人操作：

   ```bash
   python3 -m venv /tmp/fct-human-trial-env
   /tmp/fct-human-trial-env/bin/python -m pip install '.[excel]'
   /tmp/fct-human-trial-env/bin/python tests/make_ui_fixtures.py /tmp/fct-human-trial-files --trial
   /tmp/fct-human-trial-env/bin/fct-ui --port 8767 --no-browser
   ```

   Windows 可用独立环境的 `Scripts/python.exe` 和 `Scripts/fct-ui.exe`。路径可以调整；样例生成器拒绝覆盖同名文件，复做时请换一个新目录。
3. 在参与者的浏览器打开 `http://127.0.0.1:8767`。确认是本机界面，记录程序版本和浏览器版本。启动环境、安装和处理端口问题均在计时前完成。
4. 样例目录包含四份文件：`trial-book-export.csv`、`trial-posted-review.xlsx`、`trial-unit-left.csv`、`trial-unit-right.csv`；还有参与者任务卡 `PARTICIPANT_TASKS.zh-CN.md` 和主持人答案 `facilitator-expectations.json`。这些内容全部独立新造，没有来自真实业务的数据。
5. 将参与者任务卡和四份文件交给参与者。完成前不要给参与者看答案文件或本页的主持人核对表。记录起始文件哈希；不要预先在界面中替参与者选择字段。

## 开始时照读

“请用这个工具完成任务卡。我们在检查工具是否容易理解，不是在考你。遇到不确定的地方可以说出来，也可以停止。请只使用提供的新造文件。接下来 15 分钟，我会记录完成情况和需要帮助的地方，不会替你选择字段。”

开始计时。主持人不要用“这里很简单”“应该点这个”等提示影响行为。参与者主动求助时可以帮助，但要记录提示原话、时间和提示后的结果；被帮助完成不能记为独立完成。

## 任务卡与时间安排

### 任务一：建立比较（约 0–6 分钟）

打开 `trial-book-export.csv` 与 `trial-posted-review.xlsx`。Excel 选择 **Posted entries**，表头在第 **3** 行。

| 用途 | 左侧列 | 右侧列 |
|---|---|---|
| 键第一部分 | Account code | Ledger ID |
| 键第二部分 | Desk | Region |
| 数值第一项 | Book amount | Posted total |
| 数值第二项 | Fee amount | Charges |
| 币种 | CCY | Currency |

使用绝对容差 **0.05**、相对容差 **0.001**。相对容差是小数比例，0.001 等于 0.1%，不是 0.001%。运行比较。

**可观察完成标准：** 参与者自行完成两份文件、Excel sheet/表头、两组键、两组数值、两边币种和两种容差的设置；比较成功显示，并能指出左、右源文件各保留多少行。两组键的位置应成对对应，不能只按编号连接。

### 任务二：追踪问题（约 6–10 分钟）

找到一个两侧都有、但数值超过所选容差的字段。记录编号、分组、左右数值与差额。再找一个因为输入问题或币种不同而不能直接相减的条目，并说明下一步应核对什么。

使用状态筛选、源行筛选或搜索追踪来源。找到重复键时，确认每个成员仍在，而不是挑一行配对或汇总抵消。筛选显示的是**字段条目数**，不一定等于唯一源行数。

**可观察完成标准：** 参与者找到一项真实金额差异及一项被阻断的比较，引用正确的键和来源位置；没有把不同币种的相同数字解释成一致，也没有把重复键解释成已自动合并。

### 任务三：取得可带走的结果（约 10–12 分钟）

查看报告，下载完整 ZIP 包。解压后打开其中的 `report.html`，指出逐项差异文件和原始输入文件在哪里。主持人可断开外部网络检查报告仍能阅读；先保持本机服务运行，以完成下一张任务卡。全部任务结束后可停止本机服务，再确认解压报告仍能打开。不要删除参与者下载的文件。

**可观察完成标准：** 参与者获得实际文件，能在解压后的本地报告中继续阅读。报告、逐项结果与源文件都属于同一次比较；主持人会后核验 ZIP 中的哈希，不用参与者现场写代码。

### 任务四：发现旧结果失效（约 12–14 分钟）

把绝对容差改成 **0.10**，再改回 **0.05**。在重新运行前，尝试使用原先的报告和 ZIP 入口。描述界面的提示，然后明确重新比较。

**可观察完成标准：** 旧下载不能继续使用；即使设置改回原值，也需要重新运行。参与者能够区分旧结果与重新比较的结果，而不是认为界面已经自动重新计算。

### 可选任务：共同单位（剩余时间内）

比较 `trial-unit-left.csv` 与 `trial-unit-right.csv`：Batch + Item 对 Run + Code，Value A / Value B 对 Output A / Output B。文件没有币种列，明确声明共同单位 **synthetic points**，绝对容差 **0.05**，相对容差 **0**。

记录参与者是否理解“共同单位”由自己声明。此任务不允许用来绕过前一组文件中已经明确存在的 USD/HKD 冲突。时间不足可记“未进行”，不能推定成功或失败。

### 收尾（约 14–15 分钟）

询问：“哪一步最不确定？”“你是否知道哪些条目仍需要人工核对？”“如果明天换成自己的两份表，你还需要什么说明？”记录原话，不把问题改成要求正面评价的表述。

## 主持人核对表（任务结束后使用）

以下是新造样例的独立预期，不是真人观察记录。

| 核对项 | 预期 |
|---|---|
| 源行覆盖 | 左 11 行、右 10 行，全部可追踪 |
| 字段条目 | 共 28；这是字段数，不是源行总数 |
| 容差内 | 8 条 |
| 金额超差 | 2 条；001 + B 的差额分别是 0.30、0.10 |
| 币种冲突 | 2 条；003 + A，USD 对 HKD，不能相减 |
| 重复键 | 6 条；005 + A 在左侧两行、右侧一行，每行两个字段，均不自动配对 |
| 非法金额 | 2 条；006 + A 的左侧 `pending` 阻断该行两个数值字段 |
| 缺键 | 2 条；左侧空编号行仍被保留 |
| 只在左 / 只在右 | 各 2 条 |
| Excel 公式 | 2 条；009 + A 的公式不被计算或当作已验证值 |
| 相对容差 | 002 + A 的 1000 对 1001 可通过，因为允许差额是 1.001 |
| 源筛选 | paired 14 条、unpaired 14 条；left 22 条、right 20 条，均为字段数 |
| 可选共同单位样例 | 左右各 2 行；4 个字段条目中 3 项容差内、1 项金额差异 |

文件中的前导零和看似 HTML 的键都是刻意设置的文字。不能把 `001` 改成 `1`，也不能执行键文字或公式内容。

主持人可使用独立核验器检查实际下载包：

```bash
/tmp/fct-human-trial-env/bin/python tests/make_ui_fixtures.py \
  --verify-zip /path/to/downloaded.zip \
  --expectations /tmp/fct-human-trial-files/facilitator-expectations.json \
  --scenario currency

/tmp/fct-human-trial-env/bin/python tests/make_ui_fixtures.py \
  --verify-sources /tmp/fct-human-trial-files \
  --expectations /tmp/fct-human-trial-files/facilitator-expectations.json
```

核验器不导入比较引擎，会逐项核对手工预期、CSV 数值、所有 ZIP 成员哈希及 ZIP 内源文件字节。第二条命令另行核对磁盘上的原件是否仍与生成时一致。核验通过证明技术结果与这组样例一致，不证明参与者已经独立完成任务。
